## הכיוון שנבחר: A, "שולחן החלטות"

נבדקו שלושה כיוונים שונים מהותית:
- **A, שולחן החלטות:** רשימה ממוינת ופרט זה לצד זה, על נייר שקט עם צבע מותג אחד.
- **B, לוח זרימה:** קנבן כהה של כל המסע.
- **C, כרטיס ציון:** עיצוב עיתונאי סביב משרה-גיבור אחת.

נבחר A, כי העבודה היומיומית היא לעבור על רשימה ולהחליט משרה אחרי משרה. פיצול רשימה ופרט מראה פסק דין, ציון וחוסם ראשון בלי לפתוח מודאל, ושומר את ההקשר של הרשימה. מ-B נלקח ה-pipeline של ההגשות, ומ-C הציון כמספר-גיבור.

## החלטות מרכזיות

| נושא | החלטה |
|---|---|
| ניווט | סרגל צד בדסקטופ, סרגל תחתון בנייד (פחות מ-1024px). השמות מנוסחים מצד המשתמש: סקירה, לבדיקה, הגשות, קליטה, ארכיון, פרופיל. |
| לב המוצר | כל שורה מציגה ציון (מספר ומד), כותרת, חברה ותאריך, ואת החוסם הראשון. הפרט נפתח בבלוק פסק דין: ציון-גיבור, סיכוי קבלה, ההמלצה וספירת חוסמים ופערים. אחריו החוסמים ממוספרים, הפערים, ההסבר של ה-AI ותיאור המשרה. |
| ציון | כלל אחד: 70 ומעלה חזקה, 50–69 חלקית, מתחת ל-50 חלשה (קודם היו ספים של 85, 80, 70 ו-50 במקומות שונים). המספר תמיד בדיו, והמד בצבע הרצועה, מלווה במילה. |
| המלצה | "להגיש" בירוק עם ✓. "לא להגיש" בניטרלי עם ✕, כי זו עצה ולא שגיאה. אדום שמור לכישלונות ולחוסמים. |
| מיון | מומלצות קודם, אחר כך לפי ציון, ואחר כך לפי id. הסדר נשאר יציב ברענון. |
| צינור | שלוש נקודות (פענוח ← סריקה ← ניתוח) במקום פסי אחוזים מומצאים. נקודה חלולה = ממתין, נקודה מלאה עם פעימה איטית = עובד עכשיו, ✕ = השלב שנכשל. |
| כישלונות | מוצמדים לראש "איפה כל קישור עומד". ההסבר ופעולות "הדבקת טקסט ידנית", "נסה שוב" ומחיקה גלויים תמיד, ולא רק במעבר עכבר. |
| הגשות | לוח pipeline (הוגש ← שיחה טלפונית ← ראיון). כל כרטיס מציג את השלב הבא ככפתור, ותפריט "סגירה" מציג דחייה, ללא מענה, לא רלוונטי, ארכיון וחזרה לבדיקה, עם הסבר מה יקרה. |
| רענון אוטומטי | גובה שורות קבוע, מפתחות יציבים, ושינוי מצב מתחלף ברכות במקום. רשימה ופרט נגללים כל אחד בנפרד. הודעת "אין חיבור" שומרת את הנתונים האחרונים. |
| מצבים | שלד טעינה בגובה השורות האמיתיות (קודם הוצג "אין משרות" בזמן טעינה). מסך שגיאת חיבור עם "נסה שוב". מצבים ריקים עם הסבר ופעולה. משרה בעיבוד מראה את שלביה ומקום שמור לציון. |
| טיפוגרפיה | IBM Plex Sans Hebrew (עברית ולטינית מאותו שלד) ו-IBM Plex Mono לכתובות, מותקנים מקומית דרך @fontsource ובלי CDN. ספרות טבלאיות ברשימות. |
| בהיר / כהה | טוקנים לכל ערכה, ובחירה ידנית (מערכת / בהיר / כהה) בתחתית סרגל הצד, בלי הבהוב בטעינה. |
| נגישות | כל אלמנט לחיץ הוא button או a. פוקוס גלוי, ↑/↓ ברשימה, דיאלוגים עם כליאת פוקוס ו-Esc, אישורים בתוך הדף במקום confirm ו-alert, ו-aria-live לסיכום הריצה. כל צבע מלווה במילה או באייקון. ניגודיות נבדקה עם הסקריפט של dataviz (טקסט 4.5:1 ומעלה, גבולות פקדים 3:1 ומעלה). |
| RTL | מאפיינים לוגיים בלבד. כותרות באנגלית ב-dir=auto, מיושרות לימין ברשימות. כתובות ב-dir=ltr. חץ קדימה הוא ←. |

## מה נבדק
- `npm ci && npm run build` עוברים בעותק נקי של הקומיט, ו-`eslint --max-warnings=0` נקי.
- 15 בדיקות הדשבורד ב-pytest עוברות. שתי בדיקות מבנה עודכנו לשמות הקבצים החדשים, והן עדיין בודקות שהניטור מציג את כל הריצה ומשתמש ב-`jobDisplayName`.
- כל הפעולות נבדקו בדפדפן מול שרת mock, כולל אימות הבקשה שנשלחה:
  - שליחת טקסט גולמי ותצוגה מקדימה של הקישורים
  - נסה שוב, הדבקת תוכן ידנית, מחיקה עם אישור
  - הגשתי, לא רלוונטי, קידום שלב, דחייה, החזרה ללוח, שינוי סטטוס בארכיון
  - ניקוי ארכיון ושמירת פרופיל
- המסכים נבדקו בדסקטופ ובנייד (375px), בבהיר ובכהה.

## מה נשאר פתוח
- **שינוי סטטוס מתוך הפרט בארכיון** נעשה דרך תפריט הסטטוס בשורה או בראש הגיליון. אין "ביטול" (undo) אחרי פעולה, כי זה היה פיצ'ר חדש.
- **עריכה ידנית (`manual_update`)** קיימת בפרט של משרה שנכשלה. בפועל, כמו קודם, משרות שנכשלו מטופלות במסך הקליטה דרך `manual-content`.
- **מחוץ לדשבורד, לא שונה:**
  1. `DELETE /api/history` מוחק כל משרה בארכיון, כולל "ללא מענה" ו"דחייה". האישור הישן אמר "רק לא רלוונטי". עכשיו האישור אומר את האמת. אם הכוונה הייתה למחוק רק "לא רלוונטי", צריך לשנות את השרת.
  2. 135 משרות ישנות שמורות עם `job_title = "Unknown"`. הדשבורד מציג במקומן את הכתובת, אבל רק תיקון בנתונים או בסריקה יחזיר כותרות אמיתיות.
  3. ה-API לא מחזיר מתי הפרופיל נשמר לאחרונה, ולכן מוצג רק "נערך" או "נשמר".
- סקיל `frontend-design` לא היה זמין בסביבה הזו. הכיוון נבנה לפי ההנחיות של ארטיפקט Design וסקיל dataviz.
